## What this means for users

| Surface | Before | After |
|---|---|---|
| "give me insights" | Routed to RAG cache, served a stale typo-poisoned "did you mean Insighta?" answer | Routes directly to the cross-tool insights widget |
| "show me cross-tool insights" | 3 dependabot PR rows from a single tool, framed as "cross-tool" | Filtered for human PRs, separated cross-tool (sources ≥ 2) from single-source, leads with cross-tool, honest title ("X cross-tool insights (+ Y single-tool)") |
| Typing a typo ("insighta", "calandar", "depoys") | LLM generated a 100–200 token "did you mean" response that then got cached | ClarifyWidget shows 1-tap correction chips; click auto-fires the corrected query. Zero AI tokens. |
| Conversations sidebar | Showed "what?", "upload", "feedback" — useless titles, clicking loaded an old convo and the next message appended to it | Hidden by default. Underlying state still wired so `showHistory={true}` opt-in brings it back |

| Idle `/assistant` polling | ~30 requests/min while idle | ~6 requests/min while idle (~50–70% reduction) |
| Mobile composer | Bottom half hidden behind iOS Safari toolbar | Clears chrome (100dvh + safe-area-inset) |
| Mobile header | "Wolfpack Assistant" truncated to "Wol…" | Brand name visible; buttons icon-only under 640px |
| Mobile composer hint | "Cmd+Enter to send" shown but meaningless | Desktop-only |

## How a teammate verifies in production

Run through this in the deployed `/assistant` after the next Vercel deploy lands:

1. **Insights routing.** Type `give me insights` → cross-tool insights widget renders. Type `insighta` → ClarifyWidget appears with chips. Click `insights` → cross-tool insights widget renders (no manual typing).
2. **Sidebar gone.** Page loads with no conversations panel on the left. Brand name "Wolfpack Assistant" is fully visible in the header (even on iPhone).
3. **Suggestions re-entry.** Send any message → starter prompts disappear → click the "?" Suggestions icon (or type `/help`) → overlay appears with the same prompt list → Escape closes it → chat is preserved.
4. **Idle polling.** Open DevTools Network → sit on `/assistant` idle for 2 minutes → request rate should be roughly 1 every 10–15s.
5. **Mobile.** Open on an iPhone → composer is fully visible above Safari's bottom chrome. Tap composer → keyboard opens → input remains usable.

## Open items + watch list

### Pre-existing, NOT touched this session
- **`who_is` route test failure** (`src/lib/assistant/tools/__tests__/who-is-tool.test.ts:187`). Test asserts `expect(r.answer).toMatch(/\/settings\/integrations/)` but the code returns `"connect Salesforce or HubSpot at /settings."`. Either update the test or rename the route — currently failing in any full-suite run.

### Decisions made this session that future sessions should respect (or explicitly revisit)
- **Cross-tool insights are framed as HELP, never as audit/blame.** A registry guard test in `src/lib/insights/__tests__/cross-tool-generators.test.ts` blocks generator names containing `email_unread_*`, `missed_*`, `forgot_*`, `failed_to_*`. If a future generator needs to surface "you missed X" — explicitly justify it and update the guard, don't just bypass.
- **The conversations sidebar default is now `false`.** Don't flip back to `true` without solving (a) auto-derived titles being useless and (b) the "new message tacked onto old convo" UX confusion. The underlying state + API stay wired so callers can opt-in.
- **Clarify widget's `KNOWN_TERMS` list is the extension point.** When a new high-value query gets added (e.g. a future `forecasts` tool), add the canonical term + hint to `KNOWN_TERMS` in `src/lib/assistant/tools/clarify-widget-tool.ts` so typos route correctly.
- **`saveAnswer` will silently reject low-confidence answers.** This is correct behavior — but if you see analytics counts for `knowledge.answer_rejected { reason: low_confidence_clarifying_answer }` spike, it's because the AI is being asked too many ambiguous questions, not a regression. The fix is usually upstream (broader tool triggers, better starter prompts).
- **15s refocus debounce is intentional.** Don't reduce it to "feel more responsive" without first measuring the request impact — it's the single biggest contributor to the idle-traffic reduction.

### Things deferred this session
- **Sidebar / conversation search.** Users lose nothing useful from the sidebar today, but a future "find my last chat about X" feature would be valuable. Best implementation is probably a Slash-command lookup, not bringing the sidebar back.
- **Cross-tool generators for CRM-bearing scenarios.** "Deal momentum signal" (email × CRM × calendar) was scoped out because the CRM connector helpers vary by vendor (HubSpot vs Salesforce). When the CRM normalization layer matures, append to `INSIGHT_GENERATORS`.
- **Teams chat data in insights.** `listChats` + `getChatMessages` exist in `src/lib/ms-graph-chats.ts` but the per-chat fetch cost was too high to justify in this round. A future "quiet teammate" generator (cross-reference Teams DM volume vs calendar meetings) would be high-signal.
- **Smart titles for past conversations.** If the sidebar comes back, a lightweight LLM-titling pass (capped at 1 cent / conversation) would let titles like "Wolfpack-auto deploy debugging" replace "what?".

## Conversational context git can't see

- **Nick's framing was the biggest design correction this session.** Mid-implementation he flagged that `email_unread_from_meeting_attendee` was a shame surface ("the insights aren't meant to punish the team"). That reshaped the whole v2 generator philosophy — every remaining generator's title was rewritten and the registry got a guard test. Future generator design should default to helpful framings.
- **Nick observed the cache poisoning live** (typed "insighta" then "insights", got the same "did you mean" answer twice with "Zero tokens" badge). The fix is two layers (saveAnswer rejection + tighter SQL threshold + ClarifyWidget) because any single layer would have left a different gap.
- **Nick reads request volume in DevTools.** "215 requests on an idle assistant" is a direct quote. Polling chattiness is visible and judged — measure before adding any new poll, debounce by default.
- **The push for E2E coverage was explicit.** Per the engineering directive ("If a UI change is made and there is no E2E test covering it, the task is not done"), every UI-bearing commit this session shipped with a Playwright spec or a coverage-matrix row pinning it.
- **Mobile testing happens in production.** Nick checks the deployed site on his iPhone after each push. The three mobile fixes shipped because of iPhone screenshots, not jsdom. Pin every mobile fix with a real safe-area or class-based regression test so jsdom-only suites still catch the regression.
