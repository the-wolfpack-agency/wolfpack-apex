## Conversational Context (the part that matters tomorrow)
- The Azure permission was ALREADY granted. I first sent the operator into the Azure portal to check and grant admin consent for `User.Read.All`; it was already in place (green check). The real and only fix was the code re-enabling the scope. Lesson: when a directory-backed feature is empty, first confirm whether the app is even REQUESTING the scope before assuming an Azure change is needed.
- How the directory actually populates: `instinct_directory_users` is a cache. It fills only when a user whose token carries `User.Read.All` triggers the sync on the Directory page ("Refresh directory"). After the scope went live, the operator had to reconnect Microsoft once (his existing token predated the scope) and then run the sync. Reconnect alone does not sync; the picker reads the cache.
- Deploy gotcha: plain `npx vercel --prod` fails with `missing_archive` ("files should NOT have more than 15000 items, received ~44921"). You MUST pass `--archive=tgz`.
- I verified the fix by reading the prod DB directly with neonctl (project `wolfpack-apex-db` / `delicate-truth-58607318`, database `neondb`, role `neondb_owner`) to confirm the `instinct_directory_users` count and the email-domain distribution (thewolfpack.agency x13 plus external guest domains).
