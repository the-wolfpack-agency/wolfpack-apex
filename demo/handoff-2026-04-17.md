## Conversational Context (the part git can't see)

- **Vibium was discovered by the user** — created by Jason Huggins (Selenium creator). User asked me to evaluate it, I recommended it for dynamic verification of static scan findings. User approved integration across 9 modules. All use Vibium's Python API directly (NO MCP server, per global CLAUDE.md).
- **The /tools page went through ~15 iterations** to get working end-to-end on the deployed Vercel URL. The core challenge: Vercel Functions can't run Python/Chrome, so we moved compute to GitHub Actions (workflow_dispatch → poll → results). Artifact download from Vercel proved unreliable (302 redirect auth stripping), so we switched to parsing results from job logs.
- **User is non-technical-team-focused** — "Wolfpack is not deeply technical." Every UI decision should favor one-click simplicity over developer control surfaces. The /tools page is designed for Max, Meghan, Alicia — no terminal, no config, no file paths.
- **AgenticQA is the user's personal IP** — stays under nhomyk, NOT the-wolfpack-agency org. Wolfpack uses it but doesn't own it. Classic PAT (`AGENTICQA_REPO_PAT`) grants cross-repo access.
- **The user dislikes FPs as failures** — "FPs are useless. FPs as a failing result is a bad design." Led to the baseline comparison fix in security-self-scan.yml. Pipeline should only fail on NEW, confirmed findings.
- **User pushback on my process**: I shipped the first Instinct commit without reading wolfpack-apex/CLAUDE.md (had wolfpack-auto's loaded). User caught it: "did you reference your claude file and template?" Lesson saved to memory.
- **Bounty pipeline is NOT priority** — user explicitly said products (Instinct, Auto) come first. Bounty scanning can wait.
