# Handoff — 2026-08-30

## Headline

Phase 1 answers content questions instead of listing them, tells the truth when
something breaks instead of blaming the client's documents, and a measured
experiment shows the SHAPE of a decision predicts its outcome without keeping
anything private.

## Conversational context (the part git cannot see)

**The defect class that ran through the whole day.** Almost everything found
was one shape: two different situations spelled identically, so no code
downstream could tell them apart. An unreachable model and an empty corpus. An
outage and a quiet week. A failure and an absence. An honest question and a
silent guess. A rating that saved and one that did not. If you find yourself
reading a zero, ask what else it could mean before believing it.

**Measuring beat reasoning every single time, and reasoning lost badly.**
Wrong hypotheses that cost real time: the four eval misses were NOT an
embedding gap (semantic is configured, all 5,006 chunks embedded, status ok);
model answers were NOT mostly failed document retrievals (235 of 247 were not
document questions at all); the rating control was NOT broken (it works, 27
uses in the product's life). Each of those felt obvious and each was wrong.

**Two near-misses worth remembering, both from checking a proxy.** A Playwright
hit test returned "covered" for a button that was merely below the fold, and a
`/playbook` check reported broken tables when it had simply never logged in.
Both would have been reported as regressions. Stand where the reader stands.

**The verify suite lies under load.** Three runs reported 29 to 32 failures
across MFA, polling, cron, search and Tools API, all green on a clean re-run,
every time caused by a dev server or Playwright still running. `verify.sh` now
warns about this at the start and repeats it in the summary if anything failed.

**What we decided NOT to build, and why.**

- Query expansion for vocabulary mismatch. Measured as no help; cross-source
  redundancy is the better answer once CRM and DMS land.
- Asking people to rate answers more. 27 ratings across 16,332 answers in the
  product's life. A product that needs ratings in order to learn will not
  learn. Recorded in `answer-outcomes.ts` so it does not get re-proposed.
- `getAllEnterpriseInteractions`, Microsoft's Copilot API that returns full
  prompts and replies. Refusing it is the pitch, not a limitation.
- Changing correct code to satisfy three `js/file-access-to-http` alerts.
  Reading a document and sending its text to an embedding API is what ingestion
  IS. Those want dismissing with a reason.
- Anything cross-client for the gist. It needs a second engagement to prove,
  and there is no second engagement yet.

**The gist result, and the honest caveat.** Nine gist features predict a bad
outcome on 12,037 real turns; `origin=ai` fails at roughly 8x the base rate.
The first run reported a feature at lift 27.9 that was circular (a dead end is
DEFINED as a miss nobody followed up), and removing it is why the numbers are
trustworthy. The thesis holds on OUR data. It has not been shown to compound
across engagements, because that needs a second client.

## Known blockers

- **No second client engagement**, which is the only real test of the gist.
- **`Reports.Read.All` is tenant-wide admin consent.** Do not bundle it into
  the Phase 1 grant. The playbook asks for a hand-exported CSV instead, which
  answers the same question this month at no cost to anybody.
- **Four code-scanning alerts are load-bearing write scopes** (committing lint
  fixes, merging Dependabot PRs, PR comments, triggering workflows) and three
  are the product working as designed. They want dismissing with a reason
  rather than a patch; that is a judgement call, not a code change.
- **Outcome labels remain the scarce input.** 19,613 decisions, 14 ratings.
  Derived labels work on our own data because we know what our answers mean.
  A client's system would give decisions in abundance and outcomes barely at
  all, which is the same wall one layer out.
