## Feature Summary — everything new this session

### 1. Setup wizard is server-state-driven
- **Bug fixed**: clicking Connect on Step 3 → navigate → back no longer restarts from Step 0.
- Wizard reads `/api/workspace/status` → `nextStep` field → derives step. Refetches on mount + window focus so OAuth round-trips resume cleanly.
- New `PUT /api/workspace` persists workspace name + upserts caller as active team member.
- Step 1 now saves to the server (previously `useState`-only, never persisted).
- Shared `src/lib/integrations/connect.ts` helper for Microsoft / QuickBooks / Plaud, used by both `/setup` and `/settings`.
- OAuth callbacks honor `?returnTo` when it begins with a single `/` (same-origin only).
- `src/lib/setup-draft.ts` persists in-progress workspace name + invites to sessionStorage — nothing typed is ever lost to navigation or reload.
- Migration 016: `instinct_setup_events` table + `instinct_setup_funnel` view (per-step viewed / completed / abandoned with median duration).
- New analytics events: `system.setup_step_viewed`, `system.setup_step_abandoned`, `system.setup_integration_connect_started/succeeded/failed`.
- 47 new tests.

### 2. Crypto-agility wrapper (quantum-migration-ready)
- `src/lib/crypto/algorithms.ts` — named algorithm registry.
- `src/lib/crypto/sign.ts` — `signToken()` / `verifyToken()` route every JWT op.
- Registered algorithms: `hs256` (current), `rs256`, `es256`, `ml-dsa-65-hybrid` (reserved — throws `NotImplementedError`).
- Every call carries `quantum_safe: boolean` in analytics so adoption is measurable.
- Migrating to ML-DSA (NIST FIPS 204) in 2027-2029 becomes a single registry entry, not a refactor.

### 3. JWT TTL hardening + refresh-token rotation
- Access-token TTL: 8h → **15 minutes**. Shrinks the harvest-now-decrypt-later window to near-zero.
- Refresh tokens: 7-day lifetime, rotated on every use.
- **Theft detection**: re-use of a revoked refresh token revokes the entire token family + emits `system.refresh_token_reuse_detected` (tripwire-grade signal into the learning system).
- New endpoint: `POST /api/auth/refresh`.
- Migration 017: `instinct_refresh_tokens` table (family_id, revoked_at, used_at).

### 4. Cookie hardening
- Single `setAuthCookie()` helper enforces `HttpOnly` + `Secure` (prod-only) + `SameSite=Lax/Strict` + `Max-Age` matching TTL.
- No direct `cookies().set()` for auth cookies anywhere — flags cannot drift.

### 5. CSP enforce mode + secondary headers
- CSP: `unsafe-eval` removed, `frame-ancestors 'none'`, `report-uri /api/csp-report` (authless report endpoint, writes `system.csp_violation_reported`).
- Added: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, minimal `Permissions-Policy`.
- HSTS left to Vercel edge (no duplication — one source of truth).

### 6. Public `/security-posture` page
- `docs/security-posture.md` — crypto inventory, PQ migration roadmap, customer-facing messaging.
- Served at `/security-posture` (public GET, unauthenticated).
- Marketable as "crypto-agile, quantum-migration-ready."

### 7. Hybrid TLS verification
- `scripts/verify-tls-hybrid.sh` checks `X25519MLKEM768` negotiation on prod.
- CI-gated test asserts hybrid TLS is live (activates when `PROD_DOMAIN` env var is set).
