## TL;DR

Built and shipped a complete **in-house survey platform** inside Instinct, end to end, and wired it to the existing QR module. It's live on `wolfpack-instinct.vercel.app` (deploys from `the-wolfpack-agency/wolfpack-apex`, branch `main`). 17 commits today; current HEAD `325c4ae`.

Two client-ready surveys are seeded and published for the **"A Weekend with Porsche"** program, at separate URLs for A/B comparison:
- **v1** `/s/weekend-porsche` — porsche.com theme (white canvas, Guards Red, Porsche Next).
- **v2** `/s/weekend-porsche-2` — pitch-deck theme (sage green on near-black).

## What's live

- **Survey builder** `/admin → /surveys` (left-nav "Surveys"): create/edit surveys, 7 question types (short/long text, single/multiple choice, rating, email, section), helpText, "Other" free-text, max-selections, conditional `visibleIf`, custom vanity slugs, brand theme selector, **upload-from-JSON** (paste or .json file), publish/unpublish lifecycle, per-survey **QR generate/show**, and a results/insights panel.
- **Public responder** `/s/<slug>`: anonymous, rate-limited, server-validated answers; renders all question types; brand theme + official Porsche wordmark (masked SVG, recolors per theme) for porsche* themes.
- **Analytics funnel** (beats a form SaaS): view beacon + completion rate + time-to-complete + device/geo/referrer attribution + per-question aggregate incl. "Other" themes. Every action emits typed `survey.*` analytics + (admin mutations) hash-chained `recordAudit`.
- **QR integration**: survey → QR code via the QR module; idempotent linking (no dup codes); "Manage in QR Codes →" deep-links to `/qr?code=<id>` (scrolls/highlights/opens that code); QR **deletion-lock** so an active code can't be archived by accident.

## CRITICAL infra fix (read this)
The migrate runner (`src/db/migrate.ts`) was globbing **all** `*.sql` including `.down.sql`, executing rollback files as forward migrations (survived only by sort-order + `IF EXISTS`). **Fixed**: forward discovery now excludes `.down.sql` (`isForwardMigration`), and there's a real `rollback(name)` (+ `tsx src/db/migrate.ts down <name>` CLI). Guard test in `src/db/__tests__/migrate-discovery.test.ts`. Going forward, `.sql` = forward, `.down.sql` = deliberate rollback only.

## Gotchas / conventions established
- **Per-survey theming is tokens-first**: the responder uses `var(--wp-*, fallback)`; `surveyThemeVars(theme)` in `src/app/s/[slug]/theme.ts` sets those vars on the page wrapper and the whole form re-skins. Add a new client brand = add a palette there + a `SURVEY_THEMES` entry. No per-component edits.
- **Porsche wordmark** is `public/brand/porsche-wordmark.svg` rendered via CSS mask (`backgroundColor: var(--wp-text)`), so it recolors per theme. Shown for any theme where `isPorscheTheme()` is true.
- **Public surfaces** (`src/app/s/`, `/api/s/`) use raw fetch by design (anonymous, no JWT) — allowlisted in `no-raw-api-fetch.test.ts`.
- **Seed drift guards**: migrations 163/165 embed the survey JSON; tests assert it matches `src/lib/surveys/__fixtures__/weekend-with-porsche.ts`. If you change the fixture, regenerate the seed SQL.
- **QR liveness**: a survey can keep a `qrCodeId` whose code was archived → `listSurveys` returns `qrActive` (LEFT JOIN); the builder shows "Regenerate QR" instead of a dead "Show QR".
