## Things that bit us today (tribal knowledge)

- **The /sites editor-vs-live divergence was a one-line bug with a load-bearing consequence.** The synthetic `RenderBrief` renderer is correct for instant-feedback during edits but does not know about template-side assets. Anyone building a new "preview mode" for anything in this app: default to the deployed URL, only swap in synthetic render when there are actual pending edits.
- **`tripleWriteEvent` is a good back-stop.** The learning loop sees every mutation through the analytics event stream even when a resource doesn't have a dedicated vector re-sync. So "no tripleWriteX helper for resource Y" is not a data-loss risk — it's just a latency risk for retrieval freshness.
- **Disjoint file sets + reserved migration numbers + disjoint analytics namespaces** let three parallel agents compose 39-file diffs without a single conflict. The shared file (`src/lib/analytics.ts`) got clean-merge inserts because each agent was told what namespace prefix to own.
- **MS Graph `onlineMeeting.joinUrl` is nested one level.** The `CalendarEvent` type now unwraps it up front so downstream components don't have to guess.

### Wave 2 tribal knowledge
- **`fanoutToTeam` is the pattern to reuse** for any future "notify the team on X" feature. One helper, one analytics event, per-recipient failure isolation, optional `excludeActor` (usually want this — don't ping yourself for your own action).
- **jest + React components that call `element.scrollIntoView()`** — jsdom doesn't polyfill it. Stub `Element.prototype.scrollIntoView` in `beforeAll` of affected test files until/unless a global jest setup is added.
- **Testid collisions under React StrictMode double-mount** — prefer `getAllByTestId(...)[0]` or `.length > 0` assertions over `getByTestId` when the component might render a reply/row from multiple panels on the same screen.
