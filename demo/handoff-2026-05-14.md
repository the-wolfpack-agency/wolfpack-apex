## Conversational Context (the part git can't see)

- **Live regression report mid-session.** You sent a screenshot of 5 assistant responses where every answer was tagged "From knowledge base / Zero tokens" — including totally novel questions ("what is Nurburgring?", "what is quantum computing?"). The label was correct: the AI fallback was never firing. Two compounding bugs (KB trigram over-match + A1 confidence gate rejecting zero-hit answers) were silently swapping every general-knowledge reply for the canned "I don't have a confident answer." Both fixed in `a8b8def`. Live now.
- **Your question "why didn't tests catch this" is the actual finding.** The unit tests mock `searchKnowledge` to return either `[]` or a single relevant hit — never a loosely-similar-but-wrong hit. Same pattern for page-facts tests. There is no eval harness that asserts "off-topic question → source must be `ai`, not `knowledge_cache`." That gap is the strategic next investment (option #3 from earlier in the day, now elevated). Today's fix adds the first three eval-style tests under the `regression 2026-05-14` block in [assistant.test.ts](../src/lib/__tests__/assistant.test.ts).
- **Calendar bug class came in via the same channel.** "What's on my calendar for Monday" returning today's meetings was the entry point — same bug shape (timeframe parser falling through to today's-default without raising). The user's prompt "How can we get more accurate? Or is there a way we can suggest a user specifies?" was directly answered: parser now recognizes weekday names + compound phrases ("Monday of next week"), and falls back with a clarifying nudge only when input is genuinely unparseable.
- **Pipeline failure on run 25887380989** was a YAML type mismatch — the wolfpack-apex Red Team caller passed `apply: 'false'` (string) to a reusable workflow declaring `apply: boolean`. Fixed by removing the quotes. Same shape to watch for in other AgenticQA-core caller workflows.
- **Multi-workspace ranking.** Of the three deployment-readiness items I laid out, you picked #1 (multi-workspace switch) explicitly because the others were quality-of-life rather than deployment blockers. #2 (Salesforce/QuickBooks OAuth) and #3 (tool-dispatch transparency) are deferred but tracked below.

## Open Items / What's Next

**Highest-ROI next move: eval harness for answer relevance.**
Today's regression was the perfect case study — unit tests can't catch "this answer is technically returned, but it's about the wrong topic." Build a small corpus of (question, must-not-cite, expected-source) cases and run them on every PR. The first 10–20 cases would have caught both bugs we shipped today.

**Remaining client-readiness items from the original triage:**
- **#2 Salesforce / QuickBooks OAuth refresh.** Vendor presets exist with static-bearer auth headers. Real Salesforce/QBO use OAuth access tokens that expire in ~2 hours. Without refresh logic, the connector works for one demo and dies overnight. Needs: OAuth handshake routes per vendor, refresh-token storage column on `instinct_connector_credentials` (or sibling table), refresh-on-401 logic in `rest-connector.ts`.
- **#3 Tool-dispatch transparency.** Surface a small expandable trace under every assistant answer: `via get_calendar_availability(timeframe="Monday") · resolved="Monday 2026-05-18"`. Wire the trace into analytics so we can later turn it into an auto-eval feedback loop. This is the foundation for "user marked this wrong → regression test next PR."

**Multi-workspace follow-up that today's work didn't cover:**
- UI to create a second workspace. The schema + auth path supports it, but there's no admin route yet — a manual `INSERT INTO instinct_workspace` is still required to spin up a tenant. Low priority until we have a second client.
- Migration 137 has a FK constraint to `instinct_workspace(id)` with `ON DELETE RESTRICT`. Before deleting any workspace row, we'll need a workspace-soft-delete path. Not urgent.

**Calendar/timeframe follow-ups (deferred — only if regressions surface):**
- Absolute date parsing ("May 18", "5/18", "next month's 15th"). Currently anything not in the weekday or fixed-token set hits the unresolved-fallback nudge. Most real questions are covered by what we shipped, but if you see the nudge fire often we'd extend.

## Known Blockers

- **27 pre-existing flaky test suites.** Same count as baseline pre-session (confirmed via stash compare). These include `dashboard-pages-render`, `EmailNavBadge`, several `automations/meeting-insights/extractors`, `no-raw-api-fetch`, etc. They fail individually but pass in isolation — most look like jest-mock state leaks across files. Not blocking today's deploy but blocking the day we promise a green-on-every-PR gate to a client. Worth a dedicated cleanup pass before the first paying tenant goes live.
- **AgenticQA-core coupling.** wolfpack-apex CI now consumes 4–5 reusable workflows from `the-wolfpack-agency/AgenticQA-core@<sha>`. When AgenticQA-core breaks (today's `apply: boolean` type mismatch), every consumer breaks simultaneously and the failure shape is `startup_failure` with no logs to point at. Consider a "reusable workflow contract" CI check on AgenticQA-core that lints caller-shape compatibility, or pin to release tags rather than commit SHAs so a bad commit doesn't ripple instantly.
- **No eval harness.** Stated above as the highest-ROI next move, restated here as a blocker because it IS the answer to "why didn't tests catch this regression." Until we have one, every prod regression of this shape costs a session round-trip to diagnose + fix.
