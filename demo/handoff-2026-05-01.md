## Architecture decisions worth remembering

- **Operating Principles is bidirectional.** SharePoint .docx is the source of truth, but in-app CRUD also writes to `instinct_principles`. Sync cron never overwrites in-app authored principles unless slugs collide.
- **JSZip+regex > mammoth for SharePoint .docx.** mammoth choked on Hoxsie's real file; ~150 LOC hand-rolled extractor handles every doc we've thrown at it. Pattern: prefer minimal hand-rolled parsers over heavyweight parser libs for constrained input formats. (Same lesson as yesterday's `qrcode-generator` swap.)
- **Validator framework is `(userId, principle) => Observation[]`.** One file per validator in `src/lib/principles/evaluators/`. Drop a file + register its `id` in `built-in-validators.ts`. No framework boilerplate.
- **Org-wide fan-out on every edit.** When a leader edits a principle in-app, we synchronously re-evaluate the entire org against it — chosen for instant scoreboard feedback over throughput. Will need to revisit if org grows >100.
- **Per-row `observed_at` is mandatory.** Flattening to "latest observation" makes trend detection ("this principle is being ignored for 3 weeks") impossible. Always store every observation, roll up at read time.
- **WPA xlsx is a real schema.** `budget-xlsx.ts` knows named ranges, tab order, formula columns. Round-trip preserves all of them — Hoxsie's existing Excel workflow is unbroken.
- **Self-service config > env vars.** Migration 119 + the in-app config pattern should be replicated for any future "needs a URL" feature.
